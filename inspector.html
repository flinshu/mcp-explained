动手实战 · MCP Inspector v2

用 MCP Inspector 看真实的 MCP 消息

动画课程里的每一条消息都是“示意”。这一篇带你用官方调试工具 MCP Inspector 连上一个真实的 MCP 服务器，亲手发出 initialize、tools/list、tools/call，再回到课程里对照着看，理解会扎实得多。

Inspector 是什么

MCP Inspector 是 MCP 官方维护的服务器调试工具（GitHub 仓库）。它扮演 MCP 客户端：连接你指定的服务器，把双方往来的每一条 JSON-RPC 消息都摆在你面前。同一个 npm 包 @modelcontextprotocol/inspector 提供三种用法：

网页版（默认）浏览器里点按钮：列工具、填参数、调用，并能看到每次调用的记录。最适合学习。
命令行 --cli一条命令一个动作，输出 JSON，适合脚本、CI 和快速验证。
终端界面 --tui在终端里交互浏览，不想开浏览器时用。

它不是网页服务，而是在你自己电脑上运行的 Node 程序，所以没法嵌进本站，需要你在本机跑。

准备工作

  1. 安装 Node.js：Inspector v2 要求 Node ^22.23.4、^24.22.1 或 >=26.12.1；下面用来练习的示例服务器要求 Node 24 及以上。直接装 Node 24 或更新的 LTS 最省事。先确认版本： 
    node -v
  2. 不用提前安装 Inspector：下面都用 npx 临时运行，第一次会自动下载。
  3. 练习用的服务器：官方的 @modelcontextprotocol/server-everything。它不干实事，专门把 MCP 的各种功能都演示一遍：工具（echo、get-sum……）、资源、提示词模板（simple-prompt）、进度通知、征询（elicitation）等，非常适合对照学习。

安全提醒：Inspector 会在本机启动服务器进程，并把 OAuth 令牌等密钥存进系统钥匙串（没有钥匙串的环境会存到 ~/.mcp-inspector/secrets.json，默认不加密）。只连接你信任的服务器；网页版默认只监听 127.0.0.1，不要改成对外开放。

实战一：网页版（推荐先做）

1. 启动

把“要连接的服务器启动命令”直接写在 Inspector 后面：

npx @modelcontextprotocol/inspector npx @modelcontextprotocol/server-everything

第一次运行时 npx 会问 Ok to proceed? (y)，输入 y 回车。Inspector 带了网页前端，首次下载可能要几分钟，之后再运行就快了。启动成功后终端会打印：

Starting MCP inspector...

MCP Inspector Web is up and running at:
   http://127.0.0.1:6274?MCP_INSPECTOR_API_TOKEN=<一串随机令牌>

   Sandbox (MCP Apps): http://127.0.0.1:6275/sandbox
   Auth token: <一串随机令牌>
   Secrets: OS keychain

Opening browser...

浏览器会自动打开这个地址。Inspector 启动了本地网页（默认端口 6274；6275 是渲染 MCP Apps 用的沙箱），并把 npx @modelcontextprotocol/server-everything 当作 stdio 服务器：作为子进程启动，通过标准输入输出、一行一条 JSON-RPC 消息来通信。传输方式

网页带有访问令牌保护：如果浏览器没有自动打开，就复制终端里那个带 MCP_INSPECTOR_API_TOKEN 参数的完整地址，不要手动去掉参数。令牌每次启动都会变，别分享给别人。用完在终端按 Ctrl+C 退出。

2. 连接：看握手

首页是 Servers 列表，里面有一张名为 npx 的服务器卡片，标着 STDIO 和 “Disconnected”。顶部那条灰色的 “Read-only session” 提示不用管：它只是说明这个服务器是在命令行里直接指定的，在网页上不能编辑。

打开卡片右上角的开关，状态会变成绿色的 “Connected”，卡片上还会显示协商出的协议版本（实测是 MCP 2025-11-25）。同时右侧会展开监控侧栏，顶部导航出现 Servers / Tools / Prompts / Resources 四个标签页。

连接这一步就是 MCP 的握手：客户端声明自己支持的协议版本和能力，服务器回复自己的版本、能力（有没有 tools、resources、prompts……）和身份。留意服务器返回的 capabilities，后面能用哪些功能全看它；卡片上的 “Connection Info” 可以查看连接详情。生命周期

看原始消息：右侧监控侧栏

侧栏有 Logs / Protocol / Console 三个标签页。Protocol 就是“消息流”：每条 JSON-RPC 消息一张卡片，标着方向（CLIENT → SERVER 或 SERVER → CLIENT）、方法名、耗时和状态。点卡片右下角的展开按钮，可以看到完整的请求参数（Parameters）和响应（Response）。卡片上还有 Replay（原样重发）和 Edit and replay（改了再发）按钮。标题旁的 LEGACY 表示当前用的是 2025 年那一代协议。

刚连上时，你就会在 Protocol 里看到服务器主动发来的消息，比如 roots/list 请求（服务器问客户端“你开放了哪些目录”）和 notifications/tools/list_changed 通知。这说明 MCP 是双向的：服务器也能向客户端发请求。根目录

小知识：server-everything 同时支持两个“时代”的协议。2025 年的客户端用 initialize 握手；2026-07-28 版本取消了握手，改为每个请求都带上版本和能力（server/discover）。你看到的是哪一种，取决于 Inspector 和服务器协商的结果。在课程页面顶部切换规范版本，就能对比两种流程。

3. 列出并调用工具

  1. 点顶部的 Tools。左边会自动列出全部工具（实测 21 个），这背后就是 tools/list。每个工具显示标题和名字，比如 “Echo Tool” 下面的 echo。工具多时可以打开 “Paginated” 开关，体验分页加载（nextCursor）。工具
  2. 选中 Echo Tool。详情里的 READ-ONLY、IDEMPOTENT 标签来自工具的 annotations；下面的表单是根据 inputSchema 自动生成的，message * 的星号表示必填。也可以打开 “Edit as JSON”，直接写参数 JSON。
  3. 在 message 里填“你好 MCP”，点 Execute Tool。右边 Results 显示 Echo: 你好 MCP；下方的 History 会记录每次运行，可以重跑（Re-run），也可以勾选两次运行做对比（Compare）。
  4. 回到右侧 Protocol，展开最上面那条 tools/call，看到的就是真正发出和收到的内容：
Parameters（请求参数）
{
  "name": "echo",
  "arguments": { "message": "你好 MCP" },
  "_meta": { "progressToken": 5 }
}

Response（响应）
{
  "jsonrpc": "2.0",
  "id": 5,
  "result": {
    "content": [ { "type": "text", "text": "Echo: 你好 MCP" } ]
  }
}

注意两点：Inspector 自动在请求里加了 _meta.progressToken，意思是“如果这个调用要很久，请用这个令牌给我发进度”；响应的 id 和请求一一对应，结果放在 result.content 里。JSON-RPC

再试 Get Sum Tool（get-sum）：填 a 和 b 两个数字。表单读的就是模型决定怎么传参时看到的同一份 schema。

想看“工具调用失败”的样子：故意让参数不合法，比如 get-sum 少填一个数，看服务器返回的是 JSON-RPC error，还是带 isError: true 的结果。课程里讲过这两者的区别。

4. 资源与提示词模板

  • Resources 页面分三块：URIs（实测 8 个具体资源，resources/list）、Templates（4 个带参数的资源模板）、Subscriptions（订阅）。点一个资源就会读取并预览它（resources/read）。试试 “Summer Specials Collection”：一次读取会返回多段内容，每段都有自己的 URI。资源
  • Prompts 页面有 4 个模板：Simple Prompt（无参数）、Arguments Prompt（一个必填、一个可选参数）、Team Management、Resource Prompt（内嵌资源引用）。选一个获取，看服务器如何把模板展开成现成的消息（prompts/get）。提示词模板
  • Team Management 演示的是参数自动补全：第一个参数选了什么，会缩小第二个参数的候选值。输入时 Inspector 会向服务器发 completion/complete。

5. 进阶：进度与征询

  • 调用 trigger-long-running-operation（填 duration 和 steps），观察执行过程中陆续到达的 notifications/progress 进度通知。进度
  • 调用 trigger-elicitation-request，服务器会反过来向“用户”要一张表单，Inspector 会弹出这张表单让你填。这就是征询（elicitation）。征询

实战二：命令行

命令行模式下每条命令都必须带 --method，执行完一个动作就退出，结果以 JSON 打印出来，很适合配合脚本使用。

只握手，确认服务器活着

npx @modelcontextprotocol/inspector --cli npx @modelcontextprotocol/server-everything --method initialize

--method initialize 只完成握手：打印服务器的 serverInfo、protocolVersion、capabilities，然后断开，不调用任何东西。

列出工具、调用工具

# 列出所有工具
npx @modelcontextprotocol/inspector --cli npx @modelcontextprotocol/server-everything --method tools/list

# 调用 echo，参数用 --tool-arg 键=值
npx @modelcontextprotocol/inspector --cli npx @modelcontextprotocol/server-everything --method tools/call --tool-name echo --tool-arg message=你好

资源和提示词模板

npx @modelcontextprotocol/inspector --cli npx @modelcontextprotocol/server-everything --method resources/list
npx @modelcontextprotocol/inspector --cli npx @modelcontextprotocol/server-everything --method prompts/list

参数顺序：Inspector 自己的参数（--method、--tool-name……）可以写在服务器命令前面或后面。如果服务器自己也有一个和 Inspector 同名的参数（比如 --config），要用 -- 分隔，规则见官方说明。

放进 CI：固定版本号，并加 --yes 跳过首次安装确认，例如 npx --yes @modelcontextprotocol/inspector@2.15.0 --cli …。写 @2 不算固定，以后可能拉到更新的版本。

实战三：远程服务器与 OAuth

远程服务器走 Streamable HTTP：一个网址，所有消息都 POST 过去。地址以 /mcp 结尾时，Inspector 会自动识别传输方式：

npx @modelcontextprotocol/inspector --cli https://你的服务器/mcp --method tools/list

官方提供了一个在线示例服务器 https://example-server.modelcontextprotocol.io/mcp，但它需要 OAuth 登录。不带令牌直接请求，会得到 401，这正是授权流程的第一步。你可以用 curl 亲眼看一下：

curl -i -X POST https://example-server.modelcontextprotocol.io/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"curl","version":"0"}}}'
HTTP/2 401
www-authenticate: Bearer error="invalid_token", error_description="Missing Authorization header",
  resource_metadata="https://example-server.modelcontextprotocol.io/.well-known/oauth-protected-resource"

WWW-Authenticate 里的 resource_metadata 告诉客户端去哪里找授权服务器。之后客户端会去发现授权服务器、用 PKCE 让用户登录、换取访问令牌，再带着令牌重新请求。这些步骤在网页版 Inspector 里会自动完成，建议用网页版连接这个地址，体验完整的登录流程。授权

常见问题

报 Node 版本不符合要求？

按上面“准备工作”的要求升级 Node。用 nvm 的话：nvm install 24，然后 nvm use 24。

网上的教程命令跑不通？

很多旧文章写的是 Inspector v1。v2 改了退出码、参数顺序、-- 分隔符，以及 --config 和 --catalog 的区分。以官方迁移指南为准；确实需要旧版时可以用 npx @modelcontextprotocol/inspector@v1-latest。

想连接自己写的服务器？

把示例里的 npx @modelcontextprotocol/server-everything 换成你自己的启动命令，例如 node build/index.js 或 uv run server.py；远程服务器就换成它的网址。

常用的服务器想每次都连？

写一个 mcp.json（格式和 Claude Desktop 等客户端的配置一样，mcpServers 对象），然后用 --config ./mcp.json --server 名字 选择。详见官方配置说明。
